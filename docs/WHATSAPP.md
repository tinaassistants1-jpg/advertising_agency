# WhatsApp: что нужно, чтобы включить

Канал заложен в архитектуру, но **не реализован**. Причина не в объёме работы, а в развилке, у которой нет бесплатного варианта.

## Развилка

Групповые чаты нужны — а официальный API их не отдаёт.

| | **Meta Cloud API** (официальный) | **Baileys / whatsapp-web.js** (неофициальный) |
|---|---|---|
| Личные чаты | ✅ | ✅ |
| **Групповые чаты** | ❌ не поддерживаются | ✅ |
| Подключение | Верификация бизнеса в Meta | QR-код, как WhatsApp Web |
| Номер | Отдельный, не привязанный к обычному WhatsApp | Любой, но он «занимается» ботом |
| Кто отвечает за стабильность | Meta, с SLA | Сообщество; ломается при обновлениях протокола |
| Правила | В рамках Terms of Service | **Против ToS Meta — номер могут заблокировать** |
| Стоимость | Оплата за сессии диалогов | Бесплатно |
| Ответ на входящее | В окне 24 часов, дальше — шаблоны | Без ограничений |

Ключевое: **Meta Cloud API не умеет групповые чаты.** Групповая рассылка была в ограниченной бете и общедоступной так и не стала. То есть официальный путь закрывает ровно половину задачи.

## Рекомендация

Если WhatsApp-группы действительно нужны — **Baileys на отдельном номере**, купленной сим-карте, не на личном номере Тины и не на номере Дома. Тогда блокировка (маловероятная при человеческом темпе сообщений, но возможная) стоит симку, а не рабочий контакт.

Если хватает личных диалогов — **Cloud API**: он не сломается и не приведёт к бану.

Решение стоит принимать под конкретную задачу: сколько там групп, что они дают, и чем обернётся потеря номера.

## Что писать в коде

Всё, кроме адаптера, уже готово: `Router`, `Agent`, персоны, инструменты и планировщик от канала не зависят и заработают без единой правки.

Реализовать нужно `src/channels/whatsapp.ts` — интерфейс `ChannelAdapter` из `src/core/types.ts`:

```ts
start()                 // подключение: QR-сессия (Baileys) или webhook-сервер (Cloud API)
stop()                  // корректное закрытие
send(chatId, message)   // отправка, с разбиением длинных сообщений
onMessage(handler)      // входящее событие → IncomingMessage → handler
```

При сборке `IncomingMessage` важно:

- **`chatKind`** — у Baileys групповой JID заканчивается на `@g.us`, личный на `@s.whatsapp.net`.
- **`addressed`** — в группе: упоминание бота в `mentionedJid`, ответ на его сообщение (`quoted`), или обращение по имени (это уже проверяет `Router` через `isAddressedByName`).
- **`images`** — скачать медиа и отдать base64 с `mediaType`; ограничение по размеру — как в Telegram-адаптере (5 МБ).
- **`userId`** — стабильный идентификатор отправителя: он сверяется с `ADMIN_IDS`.
- **Свои сообщения игнорировать** — иначе бот зациклится на собственных ответах. У Baileys это флаг `key.fromMe`.

Дальше — включить в `src/index.ts` (адаптер уже подключается при `WHATSAPP_ENABLED=true`) и добавить нужные переменные в `.env.example`.

## Сессия Baileys

Учётные данные сессии (`auth_info`) нужно хранить в томе рядом с базой — иначе после каждого рестарта придётся сканировать QR заново. В Docker это ещё один `volumes:` в `docker-compose.yml`.
